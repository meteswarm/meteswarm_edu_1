# planner-comments — 기획자용 한국어 주석

화면 코드에 기획자가 읽을 수 있는 한국어 주석만 추가한다. 코드 자체는 절대 바꾸지 않는다.

## 꼭 지킬 것

1. **코드는 한 글자도 바꾸지 않는다.** 주석 줄만 새로 추가한다. 기존 코드의 동작, 스타일, 들여쓰기, 줄바꿈, 기존 주석은 그대로 둔다.
2. **개발 용어 대신 쉬운 말을 쓴다.** 예: state → "화면이 기억하는 값", props → "바깥에서 받아오는 값", onClick → "누르면", 렌더링 → "화면에 보여줌". 꼭 필요한 용어는 괄호로 병기한다. 예: "화면이 기억하는 값(state)".
3. **모르면 추측하지 않는다.** 코드나 문서로 확인되지 않는 동작은 지어내지 않고 `[확인 필요]`로 표시한다.
4. **고객 개인정보를 쓰지 않는다.** 주석이나 예시에 실제 이름, 전화번호, 이메일, 주소 등을 넣지 않는다. 코드 안의 샘플 값도 주석에 옮겨 적지 않는다.

## 작업 순서

1. **대상 확인**
   - 사용자가 지정한 파일이나 폴더만 작업한다.
   - 지정하지 않았으면 작업을 시작하지 말고 어떤 파일에 달지 먼저 묻는다.
2. **기준 문서 읽기**
   - `Reference/links.md`의 기준 우선순위를 따른다: PRD.md > screens.md > 화면 링크 > Make 링크 > flow.png
   - `Docs/PRD.md`와 `Docs/screens.md`에서 대상 화면에 해당하는 항목을 찾는다.
   - 문서를 읽지 못하면 추측하지 말고 멈추고 알린다.
3. **원본 백업**
   - 주석을 달기 전에 대상 파일을 세션 scratchpad 디렉터리에 복사해 둔다. 완료 확인 때 비교용으로 쓴다.
4. **주석 달기**
   - 아래 "주석 형식"을 따라 두 종류를 단다.
     - **화면 영역별:** 헤더, 필터, 카드 목록, 입력 폼, 하단 버튼 같은 덩어리 바로 위
     - **동작·조건:** 버튼을 누르면 일어나는 일, 언제 보이고 언제 숨는지, 입력값 검사, 에러 처리
   - 함수나 변수 하나하나에는 달지 않는다.
   - 기존 주석은 고치거나 지우지 않고 그대로 둔다.
5. **완료 확인**
   - 아래 "끝났는지 확인"을 모두 통과해야 끝난다.

## 주석 형식

모든 주석은 머리말로 시작한다. 한 주석에는 한 가지 내용만 적는다.

| 머리말 | 쓰는 곳 | 예 |
|---|---|---|
| `[영역]` | 화면 덩어리 위 | `[영역] 하단 버튼 — 신청과 취소` |
| `[동작]` | 누르기·입력·이동 | `[동작] 누르면 신청 확인 화면으로 이동` |
| `[조건]` | 보이기·숨기기·검사 | `[조건] 이름이 비어 있으면 신청 버튼을 누를 수 없음` |
| `[근거]` | 문서 출처 | `[근거] screens.md 신청 폼 화면` |
| `[확인 필요]` | 코드·문서로 확인 안 됨 | `[확인 필요] 신청 실패 시 안내 문구가 정해져 있지 않음` |
| `[불일치]` | 문서와 코드가 다름 | `[불일치] screens.md는 월 9,900원, 코드는 월 5,900원` |

- 문서와 코드가 다르면 `[불일치]`로 표시만 하고 코드는 고치지 않는다. 어느 쪽이 맞는지는 links.md 우선순위로 적을 수 있다.
- 주석 문법은 파일 언어에 맞춘다.
  - JS/TS 코드: `// [동작] ...`
  - JSX 마크업 안: `{/* [영역] ... */}`
  - CSS: `/* [영역] ... */`
  - HTML: `<!-- [영역] ... -->`
- 주석은 새 줄에만 추가하고, 기존 코드 줄 끝에 붙이지 않는다. 그래야 코드 변경 없음 검사가 가능하다.

## 끝났는지 확인

아래를 모두 통과해야 작업이 끝난다. 하나라도 실패하면 고치고 다시 확인한다.

1. **코드 변경 없음**
   - 백업과 현재 파일을 비교한다(예: `git diff --no-index <백업> <현재>`).
   - 바뀐 줄이 모두 "추가된 주석 줄"이어야 한다. 삭제되거나 수정된 줄이 하나라도 있으면 실패다.
2. **빠진 곳 없음**
   - 화면의 모든 영역에 `[영역]` 주석이 있는지 확인한다.
   - 모든 버튼, 입력, 화면 이동, 보이기·숨기기 조건에 `[동작]` 또는 `[조건]` 주석이 있는지 확인한다.
3. **실행·빌드 확인**
   - `package.json`에 `build`, `typecheck`, `lint` 같은 스크립트가 있으면 실행해 오류가 없는지 확인한다.
   - JSX 주석을 잘못 넣으면 빌드가 깨질 수 있으니 반드시 확인한다.
   - 실행할 스크립트가 없으면 "빌드 확인 생략(스크립트 없음)"이라고 알린다.
4. **개인정보 없음**
   - 추가한 주석에 고객 이름, 전화번호, 이메일 같은 개인정보가 없는지 확인한다.

## 결과

- 원본 파일에 주석을 바로 추가한다. 복사본이나 별도 요약 문서는 만들지 않는다.
- 끝나면 위 확인 결과(통과/실패)만 짧게 알린다.
